# Passation technique — DMAGA, passe 2

Aucune mission ci-dessous n’a été exécutée sur la blockchain, aucun agent de code lancé et aucun fichier GitHub modifié. Ce sont des propositions ; la consigne de cette collecte ne vaut pas autorisation de publier un PR ou de modifier le dépôt.

## Entrées et règles

- Lire le rapport et le CSV ; les IDs de source se trouvent dans le JSONL, avec variantes brutes, types de relations, dates UTC et auteurs. Les hashes de médias lus figurent dans la couverture.
- Fixer le mint officiel : `7D7BRcBYepfi77vxySapmeqRNN1wsBBxnFPJGbH5pump`. Pour chaque compte, enregistrer signatures, slots, signataires, balances et CPI. Tout champ absent reste absent.
- Reprendre le référentiel historique sans réannoncer A1–A12 comme nouveaux. La source complète d’une adresse sociale ne démontre ni contrôle du wallet ni propriétaire unique.
- Privilégier une exécution locale isolée/lecture seule et les jeux historiques déjà disponibles ; aucune recherche d’identité civile ni accès à des données privées. Si une correction du dépôt est ensuite autorisée, générateurs et sorties doivent rester cohérents.
- Pour toute mission : produire tableau de preuves, code de reproduction proposé, hypothèse alternative, statut CONFIRMED / REFUTED / UNRESOLVED et raisons. Arrêter sur données manquantes, pas inventer une signature.

## Livrable technique minimal

Un ledger par hypothèse (CSV/Parquet), des reçus bruts hachés, un index signature→slot→instruction→montant→mint, les résultats des tests de provenance et un résumé des divergences avec les anciennes fenêtres. Les estimations de PnL latent et les profits réalisés doivent être dans des colonnes distinctes. Ne pas fusionner les plafonds de financement CEX/deBridge déjà étudiés avec ces nouvelles pistes sociales.
