# Revue d'outils open source pour l'enquête (06/11/2026)

## Méthode

- Clones `git --depth 1` hors du dépôt, dans le scratchpad de session. Rien n'a été installé, compilé ni exécuté parmi le code tiers.
- « Dernier commit » : date du commit de tête de la branche par défaut au 06/11/2026, lue dans le clone (`git log -1`). Étoiles et archivage : API GitHub.
- Seuls appels réseau en dehors de GitHub : des GET sans clé vers les API publiques de Jito (`bundles.jito.wtf`, 8 appels), de deBridge (`dln.debridge.finance`, `dln-api.debridge.finance`, 5 appels) et vers Routescan (1 appel), pour juger la couverture de 2024 sur nos propres signatures. Les calculs de recouvrement plus bas sont faits par nos soins, en Python stdlib, sur les fichiers de `data/`.
- Recherches GitHub sans aucun résultat : « pumpfun analysis », « pump.fun dataset », « pumpfun sniper analysis », « bundle detector solana », « rug pull pump.fun », « sandwich solana detector », « dln debridge », « ethereum address clustering heuristics ». « pump.fun bundle » et « jito bundle » ne remontent que des bots d'exécution (bundlers, snipers).
- Ce qui n'a pas été lu est écrit « non lu ».

## Recommandation

1. **API de bundles Jito, avec les 8 comptes de pourboire dérivés.**
   - Apport : une preuve de soumission commune au slot de création et aux slots suivants. C'est plus fort qu'une co-temporalité et cela vaut pour juillet comme pour décembre 2024. Le premier test relie déjà la création de XC78 et l'achat de 74,9 % de `Go5rFkwK…`.
   - Contrôles : une transaction qui paie un pourboire doit avoir un bundle (contrôle positif) ; les signatures et l'ordre rendus se vérifient par `getBlock` sur le slot (`blockIndex` consécutifs).
   - Coût : environ 40 lignes de stdlib (`urllib`, cache par signature comme `k16_pubrpc.py`), 2 appels par transaction, et le gel des réponses JSON dans `evidence/`. C'est un index hors chaîne tenu par Jito : à citer comme tel.
2. **`liteModel` de l'API DLN**, pour combler les 45 hachages d'exécution manquants.
   - Apport : appariement exact source → destination par identifiant d'ordre, et identification du solveur qui a payé.
   - Contrôle : relire chaque exécution sur Routescan, comme dans le test, en comparant montant, receveur et `DLN_DST`.
   - Coût : environ 30 lignes et 2 appels par ordre ; le point d'API peut disparaître ou se fermer, comme `stats-api.dln.trade`.
3. **Liste d'exclusion locale** : `mev-bot` et `mev-builder` d'eth-labels, exchanges EVM et Solana de Spellbook, comptes de pourboire Jito, `ARu4n5mF…`.
   - Apport : repérer les bots et services qui restent dans `eth_kekius_wallets.csv` et les listes « top 100 ». 5 `mev-bot` ont déjà été trouvés dans les deux listes top 100.
   - Cadre : une étiquette envoie une adresse en relecture. Elle ne vaut pas REJETÉ d'office, car les listes se contredisent (`0x4976a4a0…`) et laissent des trous (aucun Binance dans eth-labels).
   - Coût : un script de jointure de 30 lignes, les sources épinglées par hachage de commit, et rien de recopié dans le dépôt public (licences BUSL-1.1 pour Spellbook, origine Etherscan pour eth-labels).

Écartés pour notre usage : carbon (perd en silence les transactions Pump.fun de 2024), les bundlers Pump.fun (outils d'exécution, non lus), OLI (clé et périmètre), onchain-money-trail-analyzer (risque). L'heuristique de l'adresse de dépôt (etherclust, Tutela) est la piste suivante pour le besoin 1, à réécrire plutôt qu'à reprendre.

## Limites de cette revue

- Aucun outil tiers n'a été exécuté : la compatibilité de solana-dex-parser avec nos transactions est déduite de son code, pas mesurée.
- Les conditions d'utilisation des API Jito et deBridge, et celles d'Etherscan, n'ont pas été lues.
- Les quotas de Dune, BigQuery et OLI n'ont pas été vérifiés.
- Les tests d'API portent sur 5 signatures Solana interrogées (4 autres rendues dans un bundle) et 1 ordre DLN. Ce sont des sondages, pas une mesure de couverture.
- Pour leidenalg, graphsense-lib et solana-sandwich-detector, seules les métadonnées GitHub ont été lues (un fichier pour graphsense-lib).
